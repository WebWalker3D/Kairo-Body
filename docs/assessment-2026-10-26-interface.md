# Interface assessment — October 26, 2026

Read-only baseline assessment of main `4b7cedf`, followed by focused repairs recorded separately. This is source evidence, not an assertion about the installed iPad or production. Reviewed the repository instructions, README, project configuration, navigation, stage, private room, shared vision, settings/provisioning, rest/capability UI and their tests. No production requests or changes were made.

## Findings

1. **P1 — Private requests lose recovery after an uncertain submission or transient polling failure.** `PrivateRoomClient.swift:81–105` generates a nonpersisted submission key and exits on the first failed GET. Backgrounding also drops the job via `stop()`. Reproduce with a successful POST whose response is lost, or one failed poll after acceptance: the UI permits another request with a new key while the original may still execute. Preserve the exact pending request/job and recover it; test accepted-but-disconnected POST, transient GET, and background/foreground without duplicate submission. Lifecycle reviewer owns the related authorization races.
2. **P1 — Session reset destroys the recovery handle without resetting the configured shared session.** `SettingsView.swift:118–120` calls `ConversationClient.clearChat()` (`264–286`), which clears pending state while the server may continue, and the next request still selects the unchanged configured Echo session. Reproduce reset during a pending job or while following configured Echo. Restrict the action to an idle iPad-local conversation, accurately name it, and guard in the client as well as the UI. Test that pending jobs and configured Echo cannot be reset.
3. **P2 — Private input over 4,000 characters disappears without feedback.** `PrivateRoomView.swift:137–147` clears the draft before `PrivateRoomClient.swift:73` silently rejects it. Reproduce by pasting 4,001 characters and sending. Validate before consuming the draft, explain the bound, and retain invalid text; test exact boundary and busy rejection.
4. **P2 — Look shows an answer unrelated to the displayed image.** `LookTogetherView.swift:75–78` renders global `conversation.reply`; image replacement clears only visual context. Reproduce a normal conversation answer, then open Look/select an image, or replace image A after discussing it. Store an image-scoped completed answer, clear it on replacement, reject late completions for old selections; test both replacement and late response.
5. **P2 — “Speak here” chooses the wrong surface's answer.** `PresenceStageView.swift:209–214` gates on Dot replay availability but chooses the latest completed turn from the all-surfaces feed without source/session matching. Reproduce a Dot answer followed by a newer Discord answer and tap Speak here. Select an explicitly identified eligible answer and expose provenance; test mixed-source ordering, empty answers and stale evidence.
6. **P2 — Saving credentials can silently delete the working credential.** `SetupView.swift:35–42`, `AppConfig.swift:49–56` and `KeychainStore.swift:27–38` delete before adding and ignore storage status, then dismiss setup. On add failure the old credential is gone and success appears unconditional. Use checked update/add, retain setup on error; test storage failure against an existing credential and new-item failure, with fake platform storage and no real tokens.
7. **P2 — Ring contact has no accessible activation.** `PresenceStageView.swift:136–139` exposes a label/hint but its only action is a drag gesture, with no accessibility action/button trait. VoiceOver activation cannot invoke the promised contact through an explicit semantic action. Add accessible contact handling using the same authorized path; verify with accessibility UI inspection and device VoiceOver acceptance.

## Scope and quality observations

The rest projection validates freshness and read-only evidence, and missing state is shown as unavailable rather than awake. Capability availability is separate from authorization in the UI. Existing tests cover those projection policies. No concrete rest/capability correctness defect was established by this review.

The sole baseline UI journey exercises unprovisioned navigation, output selection and a privacy toggle, but never submits a request, receives a reply, recovers an error, selects/replaces an image, or exercises paired private memory decisions. No baseline client tests target PrivateRoomClient, SharedVisualContext or credential-write failure. These gaps explain why visually working navigation is insufficient evidence of a working conversation appliance.

Many information labels use fixed 8–12 point fonts; large text and VoiceOver acceptance need explicit verification. No simulator or hardware layout inspection was performed in this Linux source audit, so clipping/contrast conclusions are not asserted. Hardware sensor, audio, camera, keyboard and accessibility checks remain distinct from CI compilation and model tests.
